## 4. 四种牌型

```
detect_pattern(cards, skip_clan_bomb=false) 判定优先级:
  1. 3 张及以上连续原子序数 → 顺序
  2. 1 张 → 单质
  3. 2 张同元素 & H/N/O/F/Cl → 单质（双原子分子 X₂）
  4. 同族 ≥2 不同元素 & skip_clan_bomb=false → 族炸
  5. 有机物检测（甲烷CH4/乙烷C2H6/丙烷C3H8及单一卤代物）→ 有机物
  6. 化合价可配平 → 化合物
  7. 否则 → 非法
```

## 5. 牌权轮转规则

顺时针轮转，N-1 人连续选择过时，牌权移交下一人。跳过的玩家抽 1 张牌。

**补充规则：顺序反转方向**——打出「顺序」牌型后，出牌方向反转（顺时针↔逆时针交替）。

## 6. 接牌规则

```
桌面空 → 自由出牌任意牌型
桌面单质 → 更大的单质 / 族炸
桌面化合物 → 更大的化合物 / 族炸
  例外: 溢出化合物（单分子原子数 ≥ 玩家数）→ 免疫族炸（仍可接更大化合物）
桌面有机物 → 任何牌不可接（打出即获胜）
桌面顺序 → 无大小比较，打出后复位桌面
族炸 → 接炸链（只能出族炸）
```

## 7. 接炸跳过摸牌规则

**接炸中跳过现在也摸牌**：

- 族炸接炸链中，选择跳过（不接炸）的玩家同样 **抽 1 张牌** 并标记 ⏸
- 与正常跳过完全一致，包括 **上限弃牌规则** 的检查
- 手牌达到上限时，不能直接跳过，必须进入弃牌模式（选择 1 张牌弃置）
- 日志提示："XXX 不接炸，抽1张并跳过"

## 7.5 族炸冷却规则

```
打出族炸        → 该玩家进入冷却 ❄（clan_bomb_cooling = true）
冷却期间        → 不能再出族炸（自由出牌 / 接炸链中 一律禁止）
				  · 其他牌型（单质 / 化合物 / 有机物 / 顺序）照常可出
				  · 接炸链中被轮询到时只能「跳过」（抽 1 张并标记 ⏸）
解除冷却        → 打出任意一张化合物（含有机物形态）时立即解除
```

- **冷却优先级高于接炸链**：即使场上正有别人的族炸等待被接，冷却玩家也不能接炸。
  （历史漏洞：早期实现写成 `not clan_bomb_chain_active and clan_bomb_cooling`，
  导致任何人重新拉开接炸链后，冷却玩家就能钻进来接炸，冷却形同虚设。）
- 冷却后仍可正常参与牌局：出化合物解除、或直接跳过；冷却不阻止普通出牌。
- 提示与 UI 必须同步：冷却玩家的「作为族炸打出」按钮置灰，接炸链中只显示「跳过」。

**实现**：`GameManager.play_cards()` 族炸分支（冷却校验先于链比较）→ 返回 `-3`；
`HintAdvisor` 同条件不生成族炸建议；`GameUI._update_action_panel()` 冷却时置灰/只给跳过。
回归用例：`tests/verify_clan_bomb_cooling.gd`。

## 8. 溢出化合物规则

| 条件 | 效果 |
|------|------|
| 化合物**单分子原子数** ≥ 玩家数 | **免疫族炸**（仍可被更大化合物接牌） |
| 单分子原子数 < 玩家数 | 正常接牌（更大化合物 / 族炸） |

- **口径是「一个分子的原子数」，不是「出了几张牌」**（v16.8 / B′）。
  `2Na+2Br` 是 4 张牌，但每个 NaBr 只有 2 个原子 —— 那只是两个小分子叠着打，
  和「大分子糊在桌上」完全是两回事，因此**不免疫**族炸。
  旧口径「牌数 ≥ 人数」只要多凑几张同元素就能免族炸，属于可刷的漏洞。
- 原子数取 `CompoundSolver.get_formula_atom_count(cards)`：
  优先用配平出的分子个数（`cards.size() / coefficient`），过氧根也算得准（H₂O₂ → 4 个原子）；
  配不出化学式时退化为 gcd 口径（宁可判不免疫，也不放水）。
- 例（4 人局）：`P₂O₅`（7 原子）/ `Fe₃O₄`（7 原子）/ `H₂O₂`（4 原子）→ 免疫；
  `NaBr`（2 原子，无论 2 张还是 4 张）/ `H₂O`（3 原子）/ `CO₂`（3 原子）→ 不免疫。
- 日志提示: "⚠ 溢出化合物！单分子 N 个原子≥M人，免疫族炸"
- 提示文本: "桌面溢出化合物(免疫族炸)，只能出更大的化合物 / 跳过"
- AI 同样受此规则约束（统一在 `play_cards()` 中生效）

## 9. 化合物限制规则

**卤族互化禁止**（默认规则）：F、Cl、Br、I 四种卤族元素之间不允许互相**化合**。

- F + Cl / F + Br / F + I → ❌ "卤族元素(F/Cl/Br/I)之间不可互相化合！"
- Cl + Br / Cl + I / Br + I → ❌
- Na + F → ✅ NaF（卤族 + 金属可以）
- **判定点在引擎**：`GameManager.play_cards()` 只在 `pattern == COMPOUND` 时检查
  （`is_halogen_mix()`，非法返回 `-7`）。人类「合成化合物」、AI、提示按钮三条路径共用
  这一条规则，不再各写一份补丁（旧版的 `AIPlayer._is_ai_halogen_pair()` 只是局部补丁）
- **不误伤族炸**：F + Cl 同属 VIIA 族，两张一起打出本身是**族炸**（不是化合），始终合法；
  只有带化合价（`custom_valences`）走「化合物」时才会被拦
- **可由补充规则放行**：开始页勾选「允许卤族互化」（`HalogenCheckBox`）后，
  卤素之间可以组成化合物（如 ClF），见 §16.3

### 化合物成立条件（硬规则，不可关闭）

一组牌能当**化合物**打出，必须存在一套价态分配同时满足：

1. 至少有一个正价元素和一个负价元素；
2. 按**实际张数**加权后总电荷 = 0（例：N 1 张 + Cl 3 张 → N(+3) / Cl(-1)）；
3. 正价元素的电负性 ≤ 负价元素的电负性（正价者必须更"金属"）。

由此：`N+Cl` / `Br+N` / `I+N` **不成化合物**（1:1 凑不出 0 电荷：N 价域只有 -3/+3/+5），
而 `NCl₃`（N +3 / Cl -1）、`NI₃`（N -3 / I +1）、`BCl₃`、`ClF` 成立。

- **唯一裁决点**：`GameManager.play_cards()` 里的 `CompoundSolver.get_compound_formula(cards, cv)`
  （内部 `_assign_valences`）。面板 / AI / 提示给出的任何价都要过它，空式子或 `ratio_ok == false` 即 `-1`。
- **AI / 提示的取价出口**：`CompoundSolver.get_valence_pairs()`（默认配平优先，失败再做价态搜索）。
  两者因此不会提出引擎会拒的组合；v4 开放金属价域后，低价金属（Fe 1 张 + Cl 2 张 → Fe(+2)）
  AI / 提示也能自动给出，不再只能靠玩家在面板手选。
- **人类面板**：`_update_valence_buttons()` 列出每张牌 `common_valence` 的**全部价**，玩家自选；
  UI 只预检「一正一负 + 最简比张数 + 手牌够不够」，选出的组合仍由引擎裁决 ——
  所以面板选项是**超集**（`NCl` / `ClN` 这类组合能选，但确认后会被 `-1` 拒绝）。
- **空式子不再放行**：`play_cards()` 化合物分支若 `get_compound_formula()` 为空或 `ratio_ok=false`，
  一律返回 `-1`（旧实现"给不出化学式就放行"会让 `ClN` 这类假化合物混进桌面）。
- 回归用例：`tests/verify_compound_chemistry.gd`（solver / 引擎 / 提示 / AI 四层）。

#### 多原子化合物与化学式约分（v16.8）

- **化学式按最简整数比约分，系数写在前面**：`2Na+2Br` → `2NaBr`（旧实现显示 `Na₂Br₂`）、
  `4H+2O` → `2H₂O`（旧实现 `H₄O₂`）、`3Mg+3O` → `3MgO`。
  显示层用 `formula`（带系数），命名 / 查表用 `formula_base`（不带系数）和
  `formula_key`（ASCII 最简比，如 `NaBr` / `H2O`）—— **三口径不可混用**，
  否则 `2NaBr` 会被当成名字的一部分，或者 `H₂SO₄` 拿去和 `H2SO4` 比永远不等。
- **过氧根（L1/L2）：O 取 −1，且必须成对**。
  `H₂O₂`（H 2 张 + O 2 张）、`Na₂O₂`、`K₂O₂`、`CaO₂`（Ca 1 张 + O 2 张）成立；
  O 取 −1 时张数必须是偶数且 ≥2，所以 `H₃O₃` / `Na₂O₃` 自动非法。
  判定靠**价态**（O 的 `common_valence` 由 `[-2]` 扩为 `[-2, -1]`），不靠张数比 ——
  否则 `CaO`（1 张 O）会被误判成过氧化物。
- **过氧根不能按 gcd 约分**：`H₂O₂` 的 H:O 是 1:1，gcd 会把它约成 `HO`。
  所以 O 全取 −1 时改按「过氧根个数」约分（`count(O)/2` 即分子个数）：
  `2H+2O` → `H₂O₂`、`4H+4O` → `2H₂O₂`。
- **默认配平覆盖不到的解由引擎自动补搜**：默认配平一律让 O 取 −2，
  所以 `H₂O₂` / `CaO₂` 这类过氧根、`NCl₃` / `BCl₃` 这类「非金属作正价」
  只能靠价态搜索找到。玩家 / AI 没显式选价时，`play_cards()` 会补一次
  `get_valence_pairs()` 搜索解，并把解出的价回写到 `table_custom_valences`
  （否则桌面小卡重新算化学式会显示成 `2HO`）。
- **3+ 元素不再限「每种恰好 1 张」**：面板只要求总电荷 Σ = 0，
  所以 `H×2 + S + O×4` 能出 `H₂SO₄`。配不平时提示改为逐项点名
  `H-1×2 + C+4×1 + N-3×1 → Σ = -1（需 0）`，一眼能看出哪个元素多带了。
- **AI 也会一次出多个分子**（L4a，`AIPlayer.AI_RATIO_COMPOUND`）：
  2 元素比例算得清时按最简比凑牌（`2Na+2Br` → 2NaBr），3+ 元素不参与
  （组合数 × 价态搜索会明显拖慢 AI 回合）。
- 回归用例：`tests/verify_compound_chemistry.gd`（约分 / 过氧根 / 原子数）、
  `tests/verify_overflow_compound.gd`（溢出判定口径）。

#### 价态域（v4：金属不再只认最高价）

搜索解时每个元素的候选价来自其 `common_valence`：

| 类型 | 价域 | 例子 |
|---|---|---|
| 金属 / 准金属 | **全部正价，降序**（高价优先） | Fe [3, 2]、Cu [2, 1]、Cr [6, 3, 2]、Mn [7, 4, 2] |
| 非金属 | 数据原顺序 | Cl [-1, 1, 3, 5, 7]、S [-2, 4, 6]、C [4, 2, -4] |

- **高价优先 = 主流解优先**：`Fe + 3O` → Fe(+3)（Fe₂O₃）；`Fe + O` 用 +3 电荷不平，自动退到 Fe(+2)（FeO）。
  同一组牌有多个解时，先命中的那个就是 UI / AI / 联机回放看到的那个（顺序固定 → 可复现）。
- **低价金属终于能解**：Cu₂O(Cu +1) / FeO(Fe +2) / FeCl₂(Fe +2) / MnO₂(Mn +4) / Cr₂O₃(Cr +3)
  现在自动解出；旧实现只给最高正价，这些组合只能靠玩家手选，AI / 提示给不出来。
- **C 补上 +2**：`C + O` → C(+2)/O(-2) = CO（`C + 2O` 仍取 C(+4) = CO₂，`CH₄` 仍用 C(-4)）。
- 回归用例：`tests/verify_valence_plan.gd`（数据 / 价域顺序 / 低价金属 / v3 不倒退 / 可复现性）。

#### 混合价态（v4：同一元素的多张牌可以各取不同价）

有的化合物「每种元素一个价」永远配不平，必须**同元素多价**：

- **Fe₃O₄**：3 张 Fe 取 +3/+3/+2（合计 +8），4 张 O 取 -2（合计 -8）。
  3 张 Fe 若同价，总电荷必是 3 的倍数，永远压不平 4 张 O 的 -8 —— 统一价态搜索必然无解。
- **求解顺序**：默认配平 → 统一价态搜索 → **混合价态搜索**。
  统一解永远优先（`Fe + 3O` 一定是 Fe₂O₃ 的 Fe(+3)，不会被拆成 +3/+3/+2 之类的怪解）。
- **约束不变**：至少一正一负、按实际张数总电荷 = 0、正价元素电负性 ≤ 负价元素；
  并且同一元素的所有副本必须**同号**（不许一张 Fe 当正价、另一张当负价）。
- **数据写法**：`custom_valences = {"Fe": [3, 3, 2], "O": -2}`。
  数组长度必须等于该元素的张数（`[3, 3]` 配 3 张 Fe 非法），元素不许写 0，同元素不许跨正负。
  老写法 `{"Fe": 3, "O": -2}`（int = 每张同价）完全兼容，联机事件 / 存档不用改协议。
- **面板入口**：只有「统一价态无解 + 混合价态有解」时，化合价面板顶部才出现
  「混合价态自动配平 ▶」按钮，并把方案写成 `Fe +3/+3/+2` 给人核对；平时不占位。
- **命名**：混合价态没有「一个」价态，亚铁/铁、氧化某这套构词法不成立，
  只认特殊命名表（`Fe3O4` → 四氧化三铁），表里没有就只显示化学式。
- **开销上限**：混合搜索的组合数超过 `MIXED_NODE_CAP`（5000）直接判无解 ——
  联机对局宁可这一手非法，也不能卡帧。Fe₃O₄ 只有 4 种组合，实测单次求解 < 0.1 ms。
- 回归用例：`tests/verify_valence_plan.gd`（第七~十三部分：规范化 / Fe₃O₄ / 非法写法 /
  统一解优先 / 特殊命名 / 联机指纹与事件重放 / 100 次一致 + 50 ms 上限）。

#### 特殊命名表（显示层，不参与判定）

`CompoundSolver.SPECIAL_NAMES` 用 **无下标化学式**（`formula_key`，如 `Fe3O4`）查表，
只影响日志 / 桌面 / 提示里显示的中文名：

- 修掉默认构词法的三类错名字：习惯名（H₂O = 水）、非金属作正价（CO = 一氧化碳）、
  混合价态（Fe₃O₄ = 四氧化三铁）。
- 注意化学式按「正价在前」排列：氨的 key 是 `H3N`，不是 `NH3`。
- **合法性判定完全不受影响**：表里查不到就继续走原命名逻辑（含氧酸 / 酸式盐 / 二元化合物），
  化合物能不能打出来只由价态规则决定。
- 收录上限 30 条，张数 ≤ 手牌 8 张（打不出来的组合不收录，避免误导）。

## 10. 手牌上限与弃牌规则

### 上限计算

```
手牌上限 = min(玩家数 × 4, 18)
4 人局 = 16 | 5 人局 = 18 | 6+ 人局 = 18
```

### 上限弃牌规则

- 玩家手牌数 **达到或超过上限** 时，不可正常跳过（含接炸跳过）
- 必须选择恰好 1 张手牌弃置（step_mode=3）
- 弃置后标记 ⏸ 并轮转牌权，**不抽新牌**

## 11. 比大小规则

```
族炸 > 有机物 > 化合物 > 单质
顺序无大小比较
同牌型: 原子序数和 → 小 = 大
平局: 原子质量和 → 大 = 弱
```

**族炸之间先比张数**（v16.9 修）：张数多者大（4 张 > 3 张 > 2 张），
张数相同才比原子序数和（小 = 大）。例：4 张 IA 族炸 `H+Li+Na+K`（和 34）
**压得住** 3 张 VIII 族 `Fe+Co+Ni`（和 81）；3 张 `He+Ne+Ar`（和 30）
压得住 3 张 `Fe+Co+Ni`（和 81，数值更小的更强）。

> 历史 Bug（真机日志 `玩家出 [H,Li,Na,K] → AI 2 出 [Fe,Co,Ni]` 竟然接上）：
> `compare_cards()` 写成 `if cards_a.size() >= 3: return 1`，
> 只要参数 a 是 3 张以上就无条件赢 —— `compare(a,b)` 与 `compare(b,a)` 同时返回 1
> （违反反对称性）。引擎判「能不能接」用的是 `compare(新牌, 桌面) > 0`，
> 于是任何 3 张以上的族炸都能压任何张数，**谁后出谁赢，张数完全失效**。
> 现在改成严格的「张数多者大，同张数比原子序数和」，回归见
> `tests/verify_pattern_ambiguity.gd` §4.4 / §4.5。

> **牌型以「打出时选择的牌型」为准**（`GameManager.table_pattern`），不按牌面重新推断。
> 同一批牌可能同时满足多个牌型（例：K + H 既像 IA 族炸，又能配成化合物 KH），
> 判大小、桌面显示、提示过滤都读这张牌打出去时记录的那个牌型——
> 否则会出现「下家的合法化合物被判牌不够大」这类自相矛盾的结果。

### 手牌拖拽重排（P7）

手牌默认按原子序数升序排列，每次刷新都会重新排序。玩家可以自己整理顺序：

- **拖动换位**：按住任意一张牌横向拖动超过 6px 进入拖拽 —— 原位牌淡出、指针跟一张半透明幽灵牌，
  牌列之间显示蓝色插入线，松手即落位；拖到手牌区外松手 = 放弃，顺序不变。
- **一次拖动 = 转入手动排列**：此后抽牌、出牌、换人都不会再把手牌打回「按序」，
  新抽到的牌一律追加到**末尾**，不会插进已排好的顺序里。
- **「按序 ⇅」按钮**：转入手动排列后出现在游戏页底部工具行的**最左侧**（与「显示提示 / 帮助 / 退出游戏」
  同一行、同高、间距 10），点一下立即按原子序数升序重排并退回自动模式；
  自动模式下该按钮隐藏（没有「恢复」可言）。
- **不影响出牌**：选中的牌以高亮 + 置顶标记，重排后高亮仍跟着同一张牌（P7 修复了原先按下标记忆导致的错位）。
- **可拖时机**：选牌阶段 / 弃牌阶段；选牌型、选化合价时手牌是只读参照。
- **教程关**：只有第零关的「UI 标注 / 流程介绍」两个阶段禁用拖拽（高亮框按固定坐标绘制，拖牌会让提示错位）；
  **第零关牌局练习阶段（phase 3）与第一 / 二关都可以拖** —— 早期版本把整个教程锁死，实机反馈「教程里手牌拖不动」。
- **门控实现**：`_can_reorder_hand()` 用 `tutorial_level == 0 and 1 <= tutorial_level0_phase < 3` 判定，
  不能只看 `tutorial_level == 0` —— 那同时也是「自由模式」的默认值。

### 「提示」按钮的行为

`GamePage` 的「提示」按钮是**一键代打演示**，不是一个说明开关：

1. 点一下 → `HintAdvisor` 在你这 8 张手牌里找一组**现在就能打出去**的牌（优先能直接赢的、有机物、族炸，
   其次化合物、张数多者优先），并自动帮你选中
2. 如果是化合物，连**化合价都配好**了，操作面板直接出现「确认打出」；其余牌型停在「选牌型」面板
3. 信息栏同步说明这一步在做什么（例：`提示：已选好 2 张并配好化合价 → 化合物 NaCl，点「确认打出」。`）
4. 若当前局面一张都打不出去（桌面牌比你的都大 / 牌型接不上），会直接告诉你「建议跳过或弃牌」
5. 你自己点任何一张牌、点「返回」或出完牌，提示就自动撤销（按钮也会弹起），不会留着一组假选中

> 提示给出的组合在规则上**一定合法**：它用的是与出牌校验同一套判断（含「桌面是化合物时有机物不能出」
> 这类细节），`tests/verify_hint.gd` 会用全新的一局把每条建议真的打一次做回归。

### 16.1 有机物胜利规则

#### 定义

有机物在游戏中是化合物的一种特殊子类型。为简化判断，只承认以下化合物为有机物：

- **甲烷 CH₄**：C × 1 + H × 4
- **乙烷 C₂H₆**：C × 2 + H × 6
- **丙烷 C₃H₈**：C × 3 + H × 8
- **单一卤代物**：上述烷烃中一个 H 被一种卤族元素（F/Cl/Br）替换
  - 示例：CH₃Cl（C×1 + H×3 + Cl×1）
  - 示例：C₂H₅F（C×2 + H×5 + F×1）
  - 限制：**只能包含一种卤族元素**（若包含 F 和 Cl 两种则无效）

#### 打出方式

选中正确组合的牌后，在牌型选择步骤点击「合成有机物(化合物)」按钮。

#### 胜利条件

**打出有机物后，游戏立即结束，该玩家直接获胜。**

#### 实现

- 检测函数：`CompoundSolver.gd` 中的 `is_organic()` 和 `get_organic_name()`
- 胜利判定：`GameManager.gd` 中 `play_cards()` 检测到 `ORGANIC` 类型后立即设置 `winner_index` 并结束游戏
- 牌型优先级：有机物在 `CardPatterns.detect_pattern()` 中的检测优先级高于普通化合物，低于族炸
- 牌力比较：有机物 > 化合物 > 单质（在 `CardPatterns.compare_cards()` 中体现）

### 16.2 顺序牌型规则

#### 定义

**三张及以上连续原子序数的牌**构成"顺序"牌型。

- 示例：H(1) + He(2) + Li(3) = 3张连续 → 顺序
- 示例：C(6) + N(7) + O(8) + F(9) = 4张连续 → 顺序
- 牌面元素顺序不要求严格按原子序数排列，系统会自动排序检测

#### 特性

一、由三张及以上连续原子序数的牌构成，**没有大小比较**

二、打出时，**出牌的顺序变更**：顺时针变为逆时针，逆时针变为顺时针

三、打出"顺序"的玩家选择让下一名玩家打出**一种特定牌型的牌**（单质/化合物/族炸），否则该玩家**罚抽两张牌**

四、无论被指定的下一名玩家出什么，他的下一名玩家都**自由出牌**（约束仅作用于紧邻的下一名玩家）

五、约束**只认被指定的那名玩家**：别人出牌、打族炸、接炸链结束、跳过都**不会**替它解除约束；
被指定玩家自己打出合规牌型 → 约束完成；自己跳过（含手牌上限弃牌跳过）→ 罚抽 2 张后约束结束。
打出新的顺序牌会作废旧约束（等新的指定）。

> 方向已在 `play_cards()` 里先反转，所以"下一名"= **反转方向上的下一名**（4 人局 P0 出顺序 → 约束 P3）。

#### 打出方式

选中 3+ 张牌后，系统自动检测为"顺序"牌型。在牌型选择步骤选择任意一种牌型即可（因为顺序的判定优先于其他牌型，系统会自动识别）。

#### 弹窗指定牌型

打出顺序后，会弹出对话框让玩家选择下一名玩家必须打出的牌型：
- **单质**：下一名玩家必须打出单质
- **化合物**：下一名玩家必须打出化合物（开启有机物规则时，有机物也算满足）
- **族炸**：下一名玩家必须打出族炸
- **跳过指定**：放弃约束权利，下一名玩家自由出牌

#### 实现

- 检测函数：`CardPatterns.gd` 中的 `_is_sequence()` 按原子序数排序后检查是否严格连续
- 方向反转：`GameManager.gd` 中的 `direction_clockwise` 在打出 SEQUENCE 时翻转
- 牌型约束：`GameManager.gd` 中的 `set_sequence_constraint()` 写入 `sequence_constraint` +
  `sequence_constraint_active` + `sequence_constraint_target`（目标座位，跳过空手牌玩家），
  `play_cards()` 只在 `player_index == sequence_constraint_target` 时校验
- 罚抽：`GameManager.gd` 中的 `player_fail_sequence_constraint()` 在**被指定玩家**不满足约束时罚抽2张
- UI 弹窗：`GameUI.gd` 中的 `_show_sequence_constraint_dialog()` 提供选择界面
- 牌权轮转：`next_turn()` 和 `_get_next_index_in_direction()` 已支持方向切换
- 回归测试：`tests/verify_sequence_lock.gd`（方向/target、别人不解除、族炸不解除、罚抽、快照字段）

### 16.3 允许卤族互化

#### 定义

「卤族互化」指 F、Cl、Br、I 之间互相组成化合物（如 ClF、BrCl）。默认是**硬规则禁止**，
勾选本开关后放开，仅影响「化合物」牌型。

#### 行为

| 局面 | 默认（不勾选） | 勾选「允许卤族互化」 |
|------|----------------|----------------------|
| F + Cl 走「合成化合物」 | ❌ `play_cards()` 返回 `-7` | ✅ 可出 ClF（一氟化氯） |
| F + Cl 走「作为族炸打出」 | ✅ 合法（族炸不是化合） | ✅ 合法（不受开关影响） |
| Na + F / Ca + Cl | ✅ 合法 | ✅ 合法 |
| AI 两元素化合物尝试 | 跳过纯卤族对 | 可合成 ClF（`AIPlayer._pair_valences()` 配价） |
| 「提示」按钮 | 只建议族炸，不给 ClF | 可给出 ClF 化合物提示 |

#### 实现

- 状态变量：`GameManager.halogen_exchange_allowed`（默认 `false`，`get_halogen_exchange_allowed()` 只读访问）
- 唯一判据：`GameManager.is_halogen_mix(cards)`（牌组中出现 ≥2 种卤素即命中），
  `HintAdvisor._check()` / `AIPlayer` / `GameUI._is_halogen_only()` 全部对齐同一语义
- 引擎拦截：`play_cards()` 在 `pattern == COMPOUND` 且开关关闭时返回 `-7`；
  `GameUI._handle_result()` 显示"卤族元素(F/Cl/Br/I)之间不可互相化合！"
- 人类预检：`GameUI._on_choose_compound()` 在进化合价面板之前挡一次，给出同样的文案（体验优化，不是判定点）
- 提示层：`HintAdvisor._compound_candidates()` 在开关关闭时不生成纯卤素候选，`_check()` 二次兜底
- 教程局：`init_tutorial()` 复位为 `false`（教程永远禁止卤族互化）
- 回归：`tests/verify_halogen.gd`（引擎 / 提示 / AI / UI / 教程五层）

### 16.4 元素限制

#### 定义

默认关闭：牌库 29 种元素全部上桌。打开后，牌库只保留**前 20 号元素**
（H ~ Ca：H/He/Li/Be/B/C/N/O/F/Ne/Na/Mg/Al/Si/P/S/Cl/Ar/K/Ca），
其余元素由玩家在小页的「元素池」里**逐个勾选**加入。

#### 可勾选的扩展元素（9 种，取自现有牌库）

| 分组 | 元素 | 说明 |
|------|------|------|
| 副族 | Cr / Mn / Fe / Co / Ni / Cu / Zn | 各 4 张；勾选后化合物更丰富（如 FeCl₃、CuO） |
| 卤族 | Br / I | 各 10 张；勾选后卤族族炸从 F+Cl 扩展为 4 选 2 |

> 扩展列表由 `CardDatabase.get_optional_elements()` 从 `get_element_data()` **自动派生**
> （原子序数 > 20 的元素全部列出），后续新增元素无需改 UI。

#### 牌库张数

| 元素池 | 种数 | 张数 |
|--------|------|------|
| 仅前 20 号（默认勾选状态） | 20 | 134 |
| 前 20 号 + 1 个副族 | 21 | 138 |
| 前 20 号 + 9 个扩展全勾 | 29 | 182（与不限制完全一致） |

#### 行为

| 局面 | 关闭（默认） | 开启 |
|------|--------------|------|
| 牌库构成 | 29 种 / 182 张 | 前 20 号 + 勾选扩展 |
| 手牌 / 提示 / AI | 全量元素 | 只会出现牌库内的元素 |
| 族炸 | 4 种卤素任取 2 张 | 只剩 F/Cl（未勾 Br/I 时） |
| 顺序牌型 | 1~53 连续段都可 | 只有 1~20 连续段（勾 Fe 后可用 24~30 段） |
| 打出越界元素牌 | — | `play_cards()` 返回 `-8`（兜底，正常拿不到该牌） |

#### 实现

- 牌池数据：`CardDatabase.get_base_element_symbols()` / `get_optional_elements()` /
  `get_allowed_symbols(limit, extras)` / `get_deck_size(symbols)`
- 牌库生成：`CardDatabase.generate_deck(allowed_symbols)`（传空数组 = 29 种全量）
- 状态变量：`GameManager.element_limit_enabled`（默认 `false`）+ `allowed_extra_elements`
- 判定入口：`GameManager.is_element_allowed(sym)`（前 20 号按原子序数判定，其余查勾选列表）
- 引擎拦截：`play_cards()` 对越界元素返回 `-8`；`GameUI._handle_result()` 显示"该元素不在本局牌库中"
- UI：小页元素池——9 个 `ElementChip_符号`（104×28，单行排布）+ `ElementPoolStats` 统计 +
  分隔线下的固定池清单 `ElementPoolBase0/1`（由 `get_base_element_symbols()` 生成，恒为前 20 号）；
  未开限制时 chip 压暗（0.55）提示"只是预选"，**点任意 chip 会自动打开限制**
- 教程局：`init_tutorial()` 强制 `element_limit_enabled = false`（预设手牌含 Fe 等副族）
- 回归：`tests/verify_element_limit.gd`（数据层 / 引擎 / 教程 / UI / 帮助页五层）

## 17. 结算页信息

一局结束（获胜 / AI 获胜 / 中途退出 / 初始化失败）统一进入结算页，展示：

| 区块 | 内容 | 数据来源 |
|---|---|---|
| 状态条 + 标题 | 胜利！ / 本局结束 / 游戏已退出 / 初始化失败 | `get_winner()` 的 `is_ai` 与自定义文案 |
| 描述 | 获胜者：玩家 1 / 本局未分胜负，随时再来一局 / 请返回主页重新开始 | 同上 |
| 总回合 | 本局累计换手次数 | `GameManager.turn_count`（`next_turn()` 每次 +1，`init_game` / `init_tutorial` 归零） |
| 剩余牌库 | 牌库剩余张数 | `get_database().get_remaining_count()` |
| 剩余手牌 | 获胜者手牌数；无胜者时取玩家 1 | `PlayerInfo.hand.size()` |
| 本局规则 | 有机物 ✓/✗、顺序 ✓/✗、卤族互化 ✓/✗、元素 N 种 | `get_organic_rules_enabled()` / `get_sequence_rules_enabled()` / `get_halogen_exchange_allowed()` / `get_allowed_element_count()` |

按钮去向随局面切换：

| 局面 | 主按钮 | 次按钮 | 幽灵按钮 |
|---|---|---|---|
| 自由局 | 返回主页 | 再来一局（按开始页当前设置重开） | 教学引导 |
| 教程局（第 0/1/2 关） | 返回关卡 | 再试一次（重开同一关） | 隐藏 |

> 第 0 关虽然 `tutorial_level == 0`，但 `tutorial_level0_phase >= 1`（已进入引导流程）时同样按教程局处理。
