## 4. 四种牌型

```
detect_pattern(cards, skip_clan_bomb=false) 判定优先级:
  1. 3 张及以上连续原子序数 → 顺序
  2. 1 张 → 单质
  3. 2 张同元素 & H/N/O/F/Cl → 单质（双原子分子 X₂）
  4. 同族 ≥2 不同元素 & skip_clan_bomb=false → 族炸
  5. 有机物检测（甲烷CH4/乙烷C2H6/丙烷C3H8及单一卤代物）→ 有机物
  6. 化合价可配平 → 化合物
  7. 否则 → 非法
```

## 5. 牌权轮转规则

顺时针轮转，N-1 人连续选择过时，牌权移交下一人。跳过的玩家抽 1 张牌。

**补充规则：顺序反转方向**——打出「顺序」牌型后，出牌方向反转（顺时针↔逆时针交替）。

## 6. 接牌规则

```
桌面空 → 自由出牌任意牌型
桌面单质 → 更大的单质 / 族炸
桌面化合物 → 更大的化合物 / 族炸
  例外: 溢出化合物（牌数 ≥ 玩家数）→ 免疫族炸（仍可接更大化合物）
桌面有机物 → 任何牌不可接（打出即获胜）
桌面顺序 → 无大小比较，打出后复位桌面
族炸 → 接炸链（只能出族炸）
```

## 7. 接炸跳过摸牌规则

**接炸中跳过现在也摸牌**：

- 族炸接炸链中，选择跳过（不接炸）的玩家同样 **抽 1 张牌** 并标记 ⏸
- 与正常跳过完全一致，包括 **上限弃牌规则** 的检查
- 手牌达到上限时，不能直接跳过，必须进入弃牌模式（选择 1 张牌弃置）
- 日志提示："XXX 不接炸，抽1张并跳过"

## 7.5 族炸冷却规则

```
打出族炸        → 该玩家进入冷却 ❄（clan_bomb_cooling = true）
冷却期间        → 不能再出族炸（自由出牌 / 接炸链中 一律禁止）
				  · 其他牌型（单质 / 化合物 / 有机物 / 顺序）照常可出
				  · 接炸链中被轮询到时只能「跳过」（抽 1 张并标记 ⏸）
解除冷却        → 打出任意一张化合物（含有机物形态）时立即解除
```

- **冷却优先级高于接炸链**：即使场上正有别人的族炸等待被接，冷却玩家也不能接炸。
  （历史漏洞：早期实现写成 `not clan_bomb_chain_active and clan_bomb_cooling`，
  导致任何人重新拉开接炸链后，冷却玩家就能钻进来接炸，冷却形同虚设。）
- 冷却后仍可正常参与牌局：出化合物解除、或直接跳过；冷却不阻止普通出牌。
- 提示与 UI 必须同步：冷却玩家的「作为族炸打出」按钮置灰，接炸链中只显示「跳过」。

**实现**：`GameManager.play_cards()` 族炸分支（冷却校验先于链比较）→ 返回 `-3`；
`HintAdvisor` 同条件不生成族炸建议；`GameUI._update_action_panel()` 冷却时置灰/只给跳过。
回归用例：`tests/verify_clan_bomb_cooling.gd`。

## 8. 溢出化合物规则

| 条件 | 效果 |
|------|------|
| 化合物牌数 **≥ 玩家数** | **免疫族炸**（仍可被更大化合物接牌） |
| 化合物牌数 < 玩家数 | 正常接牌（更大化合物 / 族炸） |

- 日志提示: "⚠ 溢出化合物！牌数≥N人，免疫族炸"
- 提示文本: "桌面溢出化合物(免疫族炸)，只能出更大的化合物 / 跳过"
- AI 同样受此规则约束（统一在 `play_cards()` 中生效）

## 9. 化合物限制规则

**卤族互化禁止**（默认规则）：F、Cl、Br、I 四种卤族元素之间不允许互相**化合**。

- F + Cl / F + Br / F + I → ❌ "卤族元素(F/Cl/Br/I)之间不可互相化合！"
- Cl + Br / Cl + I / Br + I → ❌
- Na + F → ✅ NaF（卤族 + 金属可以）
- **判定点在引擎**：`GameManager.play_cards()` 只在 `pattern == COMPOUND` 时检查
  （`is_halogen_mix()`，非法返回 `-7`）。人类「合成化合物」、AI、提示按钮三条路径共用
  这一条规则，不再各写一份补丁（旧版的 `AIPlayer._is_ai_halogen_pair()` 只是局部补丁）
- **不误伤族炸**：F + Cl 同属 VIIA 族，两张一起打出本身是**族炸**（不是化合），始终合法；
  只有带化合价（`custom_valences`）走「化合物」时才会被拦
- **可由补充规则放行**：开始页勾选「允许卤族互化」（`HalogenCheckBox`）后，
  卤素之间可以组成化合物（如 ClF），见 §16.3

## 10. 手牌上限与弃牌规则

### 上限计算

```
手牌上限 = min(玩家数 × 4, 18)
4 人局 = 16 | 5 人局 = 18 | 6+ 人局 = 18
```

### 上限弃牌规则

- 玩家手牌数 **达到或超过上限** 时，不可正常跳过（含接炸跳过）
- 必须选择恰好 1 张手牌弃置（step_mode=3）
- 弃置后标记 ⏸ 并轮转牌权，**不抽新牌**

---

## 11. 比大小规则

```
族炸 > 有机物 > 化合物 > 单质
顺序无大小比较
同牌型: 原子序数和 → 小 = 大
平局: 原子质量和 → 大 = 弱
```

## 13. 游戏流程

```
Start Page → 选择模式（自由/第一关/第二关）→ 勾选「有机物胜利规则」/「顺序牌型规则」/「允许卤族互化」（三个独立开关）

  ├── 172 张牌洗牌 → 每人发 8 张（或预设手牌）
  └── is_round_starter = true

回合循环:
  _refresh_ui() → 牌权状态 + 桌面 + 手牌(牌面) + 牌库计数 + 教程引导
  人类操作 → 选牌 → 选牌型 → 化合物化合价 → 打出
  有机物打出 → 立即胜利
  顺序打出 → 反转方向 + 弹出指定牌型对话框
  接炸跳过 → 抽1张（上限时弃牌）

  溢出化合物 → 免疫族炸（仍可接化合物）
  族炸 → 接炸链
  手牌 = 0 → GAME_OVER → End Page
```

### 手牌拖拽重排（P7）

手牌默认按原子序数升序排列，每次刷新都会重新排序。玩家可以自己整理顺序：

- **拖动换位**：按住任意一张牌横向拖动超过 6px 进入拖拽 —— 原位牌淡出、指针跟一张半透明幽灵牌，
  牌列之间显示蓝色插入线，松手即落位；拖到手牌区外松手 = 放弃，顺序不变。
- **一次拖动 = 转入手动排列**：此后抽牌、出牌、换人都不会再把手牌打回「按序」，
  新抽到的牌一律追加到**末尾**，不会插进已排好的顺序里。
- **「按序 ⇅」按钮**：转入手动排列后出现在游戏页底部工具行的**最左侧**（与「显示提示 / 帮助 / 退出游戏」
  同一行、同高、间距 10），点一下立即按原子序数升序重排并退回自动模式；
  自动模式下该按钮隐藏（没有「恢复」可言）。
- **不影响出牌**：选中的牌以高亮 + 置顶标记，重排后高亮仍跟着同一张牌（P7 修复了原先按下标记忆导致的错位）。
- **可拖时机**：选牌阶段 / 弃牌阶段；选牌型、选化合价时手牌是只读参照。
- **教程关禁用**：第零关（引导 + 牌局练习）与第一/二关都不允许拖拽，避免与引导高亮框冲突。

### 「提示」按钮的行为

`GamePage` 的「提示」按钮是**一键代打演示**，不是一个说明开关：

1. 点一下 → `HintAdvisor` 在你这 8 张手牌里找一组**现在就能打出去**的牌（优先能直接赢的、有机物、族炸，
   其次化合物、张数多者优先），并自动帮你选中
2. 如果是化合物，连**化合价都配好**了，操作面板直接出现「确认打出」；其余牌型停在「选牌型」面板
3. 信息栏同步说明这一步在做什么（例：`提示：已选好 2 张并配好化合价 → 化合物 NaCl，点「确认打出」。`）
4. 若当前局面一张都打不出去（桌面牌比你的都大 / 牌型接不上），会直接告诉你「建议跳过或弃牌」
5. 你自己点任何一张牌、点「返回」或出完牌，提示就自动撤销（按钮也会弹起），不会留着一组假选中

> 提示给出的组合在规则上**一定合法**：它用的是与出牌校验同一套判断（含「桌面是化合物时有机物不能出」
> 这类细节），`tests/verify_hint.gd` 会用全新的一局把每条建议真的打一次做回归。

  静止态与其它按钮同色，不与「帮助」抢注意力
- 「显示提示」以前开 / 关两态长得一模一样（都是默认灰底），现在开态是主题蓝实底，
  开着再悬停只把蓝色提亮一档（不会闪回深蓝灰）

### 桌面迷你卡牌

当桌面有牌时，`table_label` 右侧（x=500, y=178）会渲染 72×90px 的迷你卡牌：
- 显示元素符号（15px 着色）、中文名（9px）、原子序数（8px）、族（7px）、化合价（8px）、相对原子质量（7px）
- 位于手牌区（y=237）上方，避免与手牌重叠
- 鼠标悬停显示完整卡牌信息（tooltip）
- 牌面样式与手牌一致：白底圆角，悬停蓝边框
- **化合物按化学式标准顺序排列**：正电性元素在前、负电性在后，组内按电负性递增；例如次氯酸 HClO 显示为 H → Cl → O（不再跟随玩家点击顺序）
- **化合价显示实际打出时的选择**：`GameManager.table_custom_valences` 在 `play_cards()` 出牌时保存，渲染时按实际化合价显示并排序（如 HClO 显示 H+1 / Cl+1 / O-2）
- 兜底：若缺少化合价记录，`get_compound_formula()` 默认路径会把酸/氢化物中的非金属正价元素（H 恒为正价；有 O 时把电负性最小的非 H 非 O 正价元素提升为正价）识别出来，保证排序仍正确

## 16. 补充规则

补充规则集中在开始页的**「补充规则」小页**里（`SuppRulesPage`），四条开关互不影响；
开始页设置卡只保留一个入口按钮（`SupplementaryHelpBtn`，显示"补充规则 · N 项已开启 ▸"）
和一行摘要（`SuppRulesSummary`）。

| 开关 | 节点名 | 开启后 |
|------|--------|--------|
| 有机物胜利规则 | `OrganicCheckBox` | 允许打出有机物，且打出即获胜 |
| 顺序牌型规则 | `SequenceCheckBox` | 允许打出顺序牌，触发方向反转 + 指定牌型 |
| 允许卤族互化 | `HalogenCheckBox` | 卤素之间可以组成化合物（默认禁止，见 §16.3） |
| 元素限制 | `ElementLimitCheckBox` | 牌库只保留前 20 号元素 + 自选扩展（默认关闭，见 §16.4） |

四条开关的状态在开局时写入 `GameManager.organic_rules_enabled` / `sequence_rules_enabled` /
`halogen_exchange_allowed` / `element_limit_enabled` + `allowed_extra_elements`（`_init_game()` 从小页读入）；
任一开启，游戏页信息栏会显示"【补充规则】…"，结算页「本局规则」也会给出 ✓/✗ 与元素种数。

### 16.1 有机物胜利规则

#### 定义

有机物在游戏中是化合物的一种特殊子类型。为简化判断，只承认以下化合物为有机物：

- **甲烷 CH₄**：C × 1 + H × 4
- **乙烷 C₂H₆**：C × 2 + H × 6
- **丙烷 C₃H₈**：C × 3 + H × 8
- **单一卤代物**：上述烷烃中一个 H 被一种卤族元素（F/Cl/Br）替换
  - 示例：CH₃Cl（C×1 + H×3 + Cl×1）
  - 示例：C₂H₅F（C×2 + H×5 + F×1）
  - 限制：**只能包含一种卤族元素**（若包含 F 和 Cl 两种则无效）

#### 打出方式

选中正确组合的牌后，在牌型选择步骤点击「合成有机物(化合物)」按钮。

#### 胜利条件

**打出有机物后，游戏立即结束，该玩家直接获胜。**

#### 实现

- 检测函数：`CompoundSolver.gd` 中的 `is_organic()` 和 `get_organic_name()`
- 胜利判定：`GameManager.gd` 中 `play_cards()` 检测到 `ORGANIC` 类型后立即设置 `winner_index` 并结束游戏
- 牌型优先级：有机物在 `CardPatterns.detect_pattern()` 中的检测优先级高于普通化合物，低于族炸
- 牌力比较：有机物 > 化合物 > 单质（在 `CardPatterns.compare_cards()` 中体现）

### 16.2 顺序牌型规则

#### 定义

**三张及以上连续原子序数的牌**构成"顺序"牌型。

- 示例：H(1) + He(2) + Li(3) = 3张连续 → 顺序
- 示例：C(6) + N(7) + O(8) + F(9) = 4张连续 → 顺序
- 牌面元素顺序不要求严格按原子序数排列，系统会自动排序检测

#### 特性

一、由三张及以上连续原子序数的牌构成，**没有大小比较**

二、打出时，**出牌的顺序变更**：顺时针变为逆时针，逆时针变为顺时针

三、打出"顺序"的玩家选择让下一名玩家打出**一种特定牌型的牌**（单质/化合物/族炸/有机物），否则该玩家**罚抽两张牌**

四、无论被指定的下一名玩家出什么，他的下一名玩家都**自由出牌**（约束仅作用于紧邻的下一名玩家）

#### 打出方式

选中 3+ 张牌后，系统自动检测为"顺序"牌型。在牌型选择步骤选择任意一种牌型即可（因为顺序的判定优先于其他牌型，系统会自动识别）。

#### 弹窗指定牌型

打出顺序后，会弹出对话框让玩家选择下一名玩家必须打出的牌型：
- **单质**：下一名玩家必须打出单质
- **化合物**：下一名玩家必须打出化合物
- **族炸**：下一名玩家必须打出族炸
- **有机物**（仅在补充规则启用时可选）：下一名玩家必须打出有机物
- **跳过指定**：放弃约束权利，下一名玩家自由出牌

#### 实现

- 检测函数：`CardPatterns.gd` 中的 `_is_sequence()` 按原子序数排序后检查是否严格连续
- 方向反转：`GameManager.gd` 中的 `direction_clockwise` 在打出 SEQUENCE 时翻转
- 牌型约束：`GameManager.gd` 中的 `set_sequence_constraint()` 和 `sequence_constraint_active` 控制
- 罚抽：`GameManager.gd` 中的 `player_fail_sequence_constraint()` 在玩家不满足约束时罚抽2张
- UI 弹窗：`GameUI.gd` 中的 `_show_sequence_constraint_dialog()` 提供选择界面
- 牌权轮转：`next_turn()` 和 `_get_next_index_in_direction()` 已支持方向切换

### 16.3 允许卤族互化

#### 定义

「卤族互化」指 F、Cl、Br、I 之间互相组成化合物（如 ClF、BrCl）。默认是**硬规则禁止**，
勾选本开关后放开，仅影响「化合物」牌型。

#### 行为

| 局面 | 默认（不勾选） | 勾选「允许卤族互化」 |
|------|----------------|----------------------|
| F + Cl 走「合成化合物」 | ❌ `play_cards()` 返回 `-7` | ✅ 可出 ClF（一氟化氯） |
| F + Cl 走「作为族炸打出」 | ✅ 合法（族炸不是化合） | ✅ 合法（不受开关影响） |
| Na + F / Ca + Cl | ✅ 合法 | ✅ 合法 |
| AI 两元素化合物尝试 | 跳过纯卤族对 | 可合成 ClF（`AIPlayer._pair_valences()` 配价） |
| 「提示」按钮 | 只建议族炸，不给 ClF | 可给出 ClF 化合物提示 |

#### 实现

- 状态变量：`GameManager.halogen_exchange_allowed`（默认 `false`，`get_halogen_exchange_allowed()` 只读访问）
- 唯一判据：`GameManager.is_halogen_mix(cards)`（牌组中出现 ≥2 种卤素即命中），
  `HintAdvisor._check()` / `AIPlayer` / `GameUI._is_halogen_only()` 全部对齐同一语义
- 引擎拦截：`play_cards()` 在 `pattern == COMPOUND` 且开关关闭时返回 `-7`；
  `GameUI._handle_result()` 显示"卤族元素(F/Cl/Br/I)之间不可互相化合！"
- 人类预检：`GameUI._on_choose_compound()` 在进化合价面板之前挡一次，给出同样的文案（体验优化，不是判定点）
- 提示层：`HintAdvisor._compound_candidates()` 在开关关闭时不生成纯卤素候选，`_check()` 二次兜底
- 教程局：`init_tutorial()` 复位为 `false`（教程永远禁止卤族互化）
- 回归：`tests/verify_halogen.gd`（引擎 / 提示 / AI / UI / 教程五层）

### 16.4 元素限制

#### 定义

默认关闭：牌库 29 种元素全部上桌。打开后，牌库只保留**前 20 号元素**
（H ~ Ca：H/He/Li/Be/B/C/N/O/F/Ne/Na/Mg/Al/Si/P/S/Cl/Ar/K/Ca），
其余元素由玩家在小页的「元素池」里**逐个勾选**加入。

#### 可勾选的扩展元素（9 种，取自现有牌库）

| 分组 | 元素 | 说明 |
|------|------|------|
| 副族 | Cr / Mn / Fe / Co / Ni / Cu / Zn | 各 4 张；勾选后化合物更丰富（如 FeCl₃、CuO） |
| 卤族 | Br / I | 各 10 张；勾选后卤族族炸从 F+Cl 扩展为 4 选 2 |

> 扩展列表由 `CardDatabase.get_optional_elements()` 从 `get_element_data()` **自动派生**
> （原子序数 > 20 的元素全部列出），后续新增元素无需改 UI。

#### 牌库张数

| 元素池 | 种数 | 张数 |
|--------|------|------|
| 仅前 20 号（默认勾选状态） | 20 | 134 |
| 前 20 号 + 1 个副族 | 21 | 138 |
| 前 20 号 + 9 个扩展全勾 | 29 | 182（与不限制完全一致） |

#### 行为

| 局面 | 关闭（默认） | 开启 |
|------|--------------|------|
| 牌库构成 | 29 种 / 182 张 | 前 20 号 + 勾选扩展 |
| 手牌 / 提示 / AI | 全量元素 | 只会出现牌库内的元素 |
| 族炸 | 4 种卤素任取 2 张 | 只剩 F/Cl（未勾 Br/I 时） |
| 顺序牌型 | 1~53 连续段都可 | 只有 1~20 连续段（勾 Fe 后可用 24~30 段） |
| 打出越界元素牌 | — | `play_cards()` 返回 `-8`（兜底，正常拿不到该牌） |

#### 实现

- 牌池数据：`CardDatabase.get_base_element_symbols()` / `get_optional_elements()` /
  `get_allowed_symbols(limit, extras)` / `get_deck_size(symbols)`
- 牌库生成：`CardDatabase.generate_deck(allowed_symbols)`（传空数组 = 29 种全量）
- 状态变量：`GameManager.element_limit_enabled`（默认 `false`）+ `allowed_extra_elements`
- 判定入口：`GameManager.is_element_allowed(sym)`（前 20 号按原子序数判定，其余查勾选列表）
- 引擎拦截：`play_cards()` 对越界元素返回 `-8`；`GameUI._handle_result()` 显示"该元素不在本局牌库中"
- UI：小页元素池——9 个 `ElementChip_符号`（104×28，单行排布）+ `ElementPoolStats` 统计 +
  分隔线下的固定池清单 `ElementPoolBase0/1`（由 `get_base_element_symbols()` 生成，恒为前 20 号）；
  未开限制时 chip 压暗（0.55）提示"只是预选"，**点任意 chip 会自动打开限制**
- 教程局：`init_tutorial()` 强制 `element_limit_enabled = false`（预设手牌含 Fe 等副族）
- 回归：`tests/verify_element_limit.gd`（数据层 / 引擎 / 教程 / UI / 帮助页五层）

## 17. 结算页信息

一局结束（获胜 / AI 获胜 / 中途退出 / 初始化失败）统一进入结算页，展示：

| 区块 | 内容 | 数据来源 |
|---|---|---|
| 状态条 + 标题 | 胜利！ / 本局结束 / 游戏已退出 / 初始化失败 | `get_winner()` 的 `is_ai` 与自定义文案 |
| 描述 | 获胜者：玩家 1 / 本局未分胜负，随时再来一局 / 请返回主页重新开始 | 同上 |
| 总回合 | 本局累计换手次数 | `GameManager.turn_count`（`next_turn()` 每次 +1，`init_game` / `init_tutorial` 归零） |
| 剩余牌库 | 牌库剩余张数 | `get_database().get_remaining_count()` |
| 剩余手牌 | 获胜者手牌数；无胜者时取玩家 1 | `PlayerInfo.hand.size()` |
| 本局规则 | 有机物 ✓/✗、顺序 ✓/✗、卤族互化 ✓/✗、元素 N 种 | `get_organic_rules_enabled()` / `get_sequence_rules_enabled()` / `get_halogen_exchange_allowed()` / `get_allowed_element_count()` |

按钮去向随局面切换：

| 局面 | 主按钮 | 次按钮 | 幽灵按钮 |
|---|---|---|---|
| 自由局 | 返回主页 | 再来一局（按开始页当前设置重开） | 教学引导 |
| 教程局（第 0/1/2 关） | 返回关卡 | 再试一次（重开同一关） | 隐藏 |

> 第 0 关虽然 `tutorial_level == 0`，但 `tutorial_level0_phase >= 1`（已进入引导流程）时同样按教程局处理。
